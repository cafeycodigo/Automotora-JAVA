          Paso 02 · Conceptos Esenciales de Java
          
    Las 4 piezas de una clase de Modelo profesional (Vehiculo)
    
          
    
            En proyectos reales de Java, toda clase del paquete modelo sigue una estructura estándar conocida como POJO (Plain Old Java Object). Veamos qué hace cada parte en Vehiculo.java:
          
    
        
    

        
    
          
    
            
    
              1. Encapsulamiento
              private String codigo;
            
    
            
    Atributos privados (private) sin final
    
            
    
              Todos los atributos se declaran con private (y sin final cuando pueden modificarse mediante setters). Esto impide que otra clase asigne valores inválidos directamente y obliga a pasar por los métodos públicos de validación.
            
    
          
    

          
    
            
    
              2. Constructores
              public Vehiculo(...)
            
    
            
    Constructor vacío vs. parametrizado
    
            
    
              Un constructor tiene exactamente el mismo nombre que la clase y no tiene tipo de retorno. Definimos uno vacío public Vehiculo() y uno con parámetros que llama a cada set...() para validar los datos desde el primer instante.
            
    
          
    

          
    
            
    
              3. Accesores (Getters)
              get...() / is...()
            
    
            
    Lectura segura: get vs is
    
            
    
              Un getter devuelve el valor actual de un atributo privado. Para tipos String o int se usa el prefijo get, mientras que para atributos boolean la convención estándar en Java usa is.
            
    
          
    

          
    
            
    
              4. Mutadores (Setters) y @Override toString
              set...() / @Override
            
    
            
    Aduana de datos y representación textual
    
            
    
              Cada setCampo(valor) valida la regla del negocio (lanzando IllegalArgumentException si falla) y guarda en this.campo = valor. Por su parte, @Override public String toString() formatea todos los atributos de la ficha en un texto legible.

      ¿Por qué el constructor llama a los set...() en vez de asignar directo?
      
                
      
                  Si el constructor asignara los atributos directamente sin pasar por los setters, se saltaría las validaciones. Al invocar los setters dentro del constructor de Vehiculo, garantizamos que tanto al instanciar con new como al modificar después un atributo se apliquen exactamente las mismas reglas.
                
      
              
      

              
      
                
      ¿Qué pasa en memoria cuando un setter lanza IllegalArgumentException?
      
                
        
                  
      1. 01.Java reserva memoria para el nuevo objeto Vehiculo e ingresa al constructor.
        2. 
                  
      2. 02.Ejecuta cada setter en orden secuencial validando formato, longitud y rangos numéricos.
        3. 
                  
      3. 03.Si un valor incumple una regla, throw new IllegalArgumentException(...) aborta la creación inmediatamente.
        4. 
                  
      4. 04.El objeto inválido nunca llega a guardarse en el DAO.
