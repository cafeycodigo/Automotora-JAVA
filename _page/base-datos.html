Fundamentos de java.sql.*

Las 6 piezas de JDBC que debes dominar

Cuando pasamos de VehiculoDAO en memoria a una base de datos relacional, el paquete java.sql nos provee las clases estándar para conectarnos, enviar sentencias SQL y reconstruir objetos Vehiculo:

1. DriverManager & Connection

El canal de comunicación

DriverManager.getConnection(url, user, pass) autentica tus credenciales y devuelve un objeto Connection activo hacia el servidor MySQL o PostgreSQL. Centralizamos esto en ConexionBD.conectar().

2. PreparedStatement (?)

Sentencias SQL precompiladas y seguras

Nunca concatenes variables con + dentro de un string SQL. Escribe ? en la consulta y asigna cada parámetro por su posición (desde 1) con ps.setString(1, ...), ps.setInt(...) o ps.setBoolean(...).

3. executeUpdate vs executeQuery

¿Escribir o leer datos?

• ps.executeUpdate() se usa para INSERT, UPDATE y DELETE. Devuelve un int con las filas afectadas (== 1 significa éxito).
• ps.executeQuery() se usa para SELECT y devuelve un ResultSet.

4. ResultSet y filas.next()

Recorrer las filas devueltas por SELECT

El cursor de un ResultSet comienza antes de la primera fila. Cada llamada a filas.next() avanza una fila y devuelve true si hay datos. Usamos if (filas.next()) al buscar por clave única y while (filas.next()) al listar.

5. try-with-resources

Cierre automático de conexiones

Al declarar try (Connection con = ...; PreparedStatement ps = ...), Java garantiza que tanto el statement como la conexión se cierren automáticamente al salir del bloque, incluso si ocurre una excepción.

6. SQLException

Excepción verificada (Checked Exception)

SQLException es una excepción verificada: el compilador de Java exige declararla con throws SQLException en la firma del método o capturarla dentro de un bloque try / catch (SQLException ex).
