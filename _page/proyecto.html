    02 / Ahora, el DAO
    
            
    El DAO administra los datos del modelo.
    
            
    
              DAO significa Data Access Object (objeto de acceso a datos). Es una clase que concentra las tareas para guardar, buscar, actualizar y eliminar datos. Así, el resto del programa puede pedir esas operaciones sin ocuparse de cómo se recorren o modifican los datos.
            
    
            
    
              En este proyecto, esa clase es VehiculoDAO. Su atributo es una lista en memoria y sus métodos permiten guardar, buscar, actualizar y eliminar usando la patente como identificador de búsqueda.

    El almacenamiento actual
    
                
    private final ArrayList<Vehiculo> vehiculos
            = new ArrayList<>();
    
                
    ArrayList es la lista que contiene los objetos. private limita el acceso directo desde otras clases. final evita reemplazar la lista por otra, pero sí permite agregar o quitar elementos. Como no se escribe en disco, al cerrar la aplicación se pierde su contenido.
    
              
    
              
    
                
    Consulta adicional en main
    
                
    for (Vehiculo v : dao.listarElectricos()) {
    System.out.println(v.getMarca()
            + " " + v.getModelo());
}
System.out.println(dao.contarElectricos());
    
                
    listarElectricos() recorre la lista y devuelve otra lista con los vehículos cuyo isElectrico() es true. El for imprime cada resultado; contarElectricos() hace el mismo filtro, pero devuelve un número.
    
              
    
            
    

            
    
              
    
                
    Siguiendo el código
    
                
    ¿Qué hace cada método por dentro?
    
                
    Todos trabajan sobre el mismo atributo vehiculos. La lista comienza vacía cuando se construye el DAO.
    
              
    
              
    
                
    
                  
    1. Guardar y evitar duplicados
    
                  
    public boolean guardar(Vehiculo vehiculo) {
    if (vehiculo == null) return false;
    if (buscar(vehiculo.getPatente()) != null) {
        return false;
    }
    vehiculos.add(vehiculo);
    return true;
}
    
                  
    
                    
    null no se puede guardar. Luego busca si ya hay un auto con esa patente: si lo encuentra, rechaza el duplicado. Si no, add lo agrega al final y devuelve true.
    
                  
    
                
    
                
    
                  
    2. Buscar: recorrer hasta encontrar
    
                  
    public Vehiculo buscar(String patente) {
    for (Vehiculo vehiculo : vehiculos) {
            if (vehiculo.getPatente().equals(patente)) {
                return vehiculo;
            }
    }
    return null;
}
    
                  
    
                    
    El for visita cada elemento. Si la patente coincide, devuelve ese objeto inmediatamente. Si termina el recorrido sin coincidencia, devuelve null. Por eso quien llama debe comprobar si el resultado es null.
    
                  
    
                
    
                
    
                  
    3. Actualizar: encontrar y copiar campos
    
                  
    Vehiculo encontrado = buscar(vehiculo.getPatente());
if (encontrado == null) return false;

encontrado.setColor(vehiculo.getColor());
encontrado.setModelo(vehiculo.getModelo());
// También copia código, marca, año,
// tipo, transmisión y estados.
return true;
    
                  
    
                    
    Usa la patente del objeto recibido para ubicar el registro existente. Si no existe, devuelve false; si existe, copia sus demás valores al objeto guardado y devuelve true. La patente no se cambia: el setter está comentado.
    
                    
    En el main de este proyecto, primero se obtiene el vehículo con buscar y luego se cambia su color. buscar devuelve la misma referencia al objeto que está en la lista, así que ese cambio ya afecta al objeto guardado; después actualizar vuelve a copiar sus campos. Este detalle ocurre porque la lista guarda referencias a objetos, no copias independientes.
    
                  
    
                
    
                
    
                  
    4. Eliminar: quitar el registro de la lista
    
                  
    int indice = 0;
for (Vehiculo vehiculo : vehiculos) {
    if (vehiculo.getPatente().equals(patente)) {
    vehiculos.remove(indice);
    return true;
    }
    indice++;
}
return false;
    
                  
    
                    
    Compara cada patente y lleva un contador de posición. Al encontrar coincidencia, quita ese índice y devuelve true. Si no encuentra la patente, devuelve false.
    
                  
    
                
    
              
    
            
    

            
    
              
    
                
    Ejemplo del main real
    
                
    Buscar y revisar el resultado
    
                
    Vehiculo encontrado = dao.buscar("ABCD12");
if (encontrado == null) {
    System.out.println("Vehiculo no encontrado");
} else {
    System.out.println(encontrado.toString());
}
    
              
    
              
    
                
    dao.buscar("ABCD12") llama al método de búsqueda. El resultado se guarda en encontrado. Como un vehículo puede no existir, el if maneja los dos casos: null significa “no encontrado”; cualquier objeto significa “encontrado” y se puede imprimir o consultar.
    
                
    En el main actual, el programa crea 10 vehículos, los guarda, intenta guardar dos veces el mismo v10 y luego ejecuta ejemplos de listado, búsqueda, actualización, eliminación y reportes.
    
                
    La primera vez que se guarda v10, guardar devuelve true. En el segundo intento encuentra la misma patente, no lo agrega de nuevo y devuelve false.
    
                
    Si se crea un vehículo con año 2014, por ejemplo, el constructor lanza IllegalArgumentException. El main de muestra no captura esa excepción, así que el programa se detiene en ese punto y no sigue con las instrucciones siguientes.
    
              
    
            
    
          
    
      
    
    

    
    
      
    
        
    
          
    Lo que mejora el patrón
    
          
    Menos responsabilidades mezcladas.
    
          
    
            Sin un DAO, el código de la interfaz o de main tendría que recorrer y modificar la colección por su cuenta. El patrón reúne esa lógica en un solo lugar y deja claro quién hace cada trabajo.
          
    
        
    
        
    
          
    
            01 — Separación
            
    Cada clase se enfoca
    
            
    Vehiculo representa y valida un auto; VehiculoDAO administra la colección. El main coordina las llamadas.
    
          
    
          
    
            02 — Reutilización
            
    Una forma consistente de operar
    
            
    Guardar evita patentes duplicadas; las búsquedas y filtros se resuelven desde los mismos métodos, en vez de repetir ciclos por el programa.
    
          
    
          
    
            03 — Evolución
            
    Más fácil de cambiar
    
            
    El almacenamiento puede evolucionar de una lista en memoria a una base de datos manteniendo las operaciones que invoca el resto del programa.
    
          
    
        
    
        
    
          Límite actual del ejemplo: el DAO todavía usa un ArrayList, por lo que los datos se pierden al cerrar el programa; además, la ventana Swing mantiene su propia lista y aún no está conectada a VehiculoDAO. listar() también devuelve la lista interna directamente, así que quien la recibe podría modificarla sin pasar por los métodos del DAO. El patrón ordena el acceso, pero esta implementación todavía puede encapsular mejor la colección y agregar persistencia.
        
    
      
    
    
    

    
    
      
    
        
    
          
    En una frase
    
          
    El DAO ordena cómo se administra el inventario; la lista todavía no es permanente.
